## Falsification and repairs

1. **Partial publication was real, not hypothetical.** `runReflection` appended ordinary visible rows before settlement. The implementer's SIGKILL verifier explicitly expected one canonical derived row at boundary B and all rows at C while the ledger was pending. This disproved its own “all-or-nothing” wording. Canonical Sea subscription/query/projection and Thread reads now gate reflection provenance on the matching committed scope record; recovery has a separate main-only preparation reader. Failed records expose at most an empty progress marker, never their derived rows. A failure injected on the second derived append reproduces the old leak and passes after repair.
2. **Scenario publication preceded its history.** `finishPreparedEvolution` previously saved `scenarioAfter`, then appended history/marker, then settled. It now prepares hidden history/marker first and publishes entity state plus committed status in a single world save. Its regression injects a marker-write failure, checks unchanged Scenario and zero canonical prepared history, then recovers exactly once. The old hand-authored test seeded an already-published entity and even used mismatching operation provenance; that was not a valid atomicity test and was replaced with production failure injection. No compatibility branch for that unreleased format was added.
3. **Maintenance bypassed the mutation queue.** Preparation and settlement performed independent read/modify/save operations against `world.json`, racing entity edits, other Rooms and the shared `.tmp` path. They now use the existing world mutation queue; explicit unlocked settlement is used only inside that queue. Both direct service calls and runtime triggers share an active pass instead of one invocation recovering/failing another invocation's live model call. Pending guards distinguish Sea from Thread and identify the Thread.
4. **A wall-clock cursor lost history.** Forty-one source events at the same mocked millisecond produced only one call and permanently skipped event 41. Window boundaries now use stream sequence numbers. The regression processes both windows. There is no migration obligation for previous development-only maintenance markers.
5. **Stale output survived source retraction.** A model callback retracting its supporting memory still published a derived belief. Preparation and recovery now revalidate source IDs/content and the cast snapshot, including tombstones; prepared content is discarded on terminal failure. Memory projection recursively invalidates reflection descendants of corrected memories. The stale-completion and post-publication memory-retraction regressions pass. This is deliberately not a claim of complete Scenario correction or physical erasure support (see blockers).
6. **Shared Director inference received private state.** Its prompt included every participant's private goals and directional starting relationships, and could turn them into a witnessed shared development. Those private inputs are excluded from shared generation. Shared source selection now requires a nonempty cast and events actually witnessed by the complete public audience, including the user; subjective memory rows are excluded from shared-event sources. Generated developments carry their actual witness set. The compiler excludes developments from later joiners, filters known retracted sources, limits the displayed development tail, and does not reveal a conclusion to someone outside its audience. This does not establish semantic truth of arbitrary generated prose.
7. **Provider/cancellation ownership was bypassed.** Dreamer called Ollama/cloud directly or used one synthetic builtin sender `-1`, bypassing the foreground inference queue and job cancellation. It now uses `completeJob` with an individual signal and bounded input/output (32,000 / 12,000 characters). Runtime rechecks provider policy, `llmEnabled`, and profile identity before calls; cancellation retains its in-flight guard until actual completion. This prevents concurrent builtin sender reuse and queued profile/route drift through the existing router boundary. It does not prove a complete foreground-priority/resource policy.
8. **A saved Room-linked Thread trigger redirected to Sea.** It now retains the actual Thread journal scope. A regression verifies the selected archive cannot trigger Room Sea consolidation. Sandbox deletion removes its maintenance records rather than retaining prepared private payloads in failed records.
9. **Failure UI promised a retry that cannot occur.** Exhausted windows are sealed, yet Details said “Retries automatically after the next exchange.” That unconditional hint was removed. No retry/review control is claimed to exist.

## Remaining V08 blockers

These are findings against the current post-repair source, not deferred successor features.

- **Threads-only is not a privacy mode.** `getInferencePolicy` gates by provider/cloud tier, not Living World opt-in. App automatically triggers maintenance after an ordinary sandbox exchange; `schedulerRuntime` scans saved persistent Rooms. There is no coherent Threads-only versus Living World choice/authority in the current Settings contract that these writers enforce. Local-provider availability is not consent to persistent social/persona inference. Sandbox isolation alone does not satisfy the requested privacy model.
- **Dreamer is still a window summarizer, not continuing-person reflection.** `makePrompt` supplies names and the current window, but no pinned persona/canon, current goals, prior beliefs/open loops, or authorized cross-Room personal state. Automatically derived rows are excluded from subsequent source windows. `resolution` payloads contain owner/text/source IDs but no loop target; neither `deriveRoomProjection` nor `compileContext` consumes them to close an existing loop. Writing a row of that type does not implement commitment resolution. Repeated new windows can accumulate repeated interpretations without a semantic supersession contract.
- **Model prose still has historical authority.** `parseEvolutionProposal` validates shape, bounds and goal identities, not support for an occurrence. `evolveSpec` accepts arbitrary `fact/progress/resolution` text, attaches all source IDs, and the renderer presents it as situation history. The submitted evolution test used a seed about planting seeds and accepted “Mara repaired the shared tools.” Its source IDs are not evidence that the repair occurred. Reflection likewise accepts `fact`/`episode` kinds; labeling the outer event `memory.belief` does not prevent downstream episode/culture consumers treating the payload as history. A bounded proposal/interpretation/authorized-occurrence contract is still required within V08. No autonomous event generator was added to conceal this defect.
- **Scenario lifecycle correction remains incomplete.** Goal changes mutate the stored profile goals, and `status: concluded` causes `locateEvolvableScenario` to stop forever. Retraction of their sources does not reverse/recompute the goals or reopen a wrongly concluded situation. The compiler's new source/witness filtering prevents some disclosure, but cannot repair this durable lifecycle. Existing-person Scenario refs are excluded from goal updates altogether (`temporaryIds`, `evolveSpec`), so the claimed evolution is also incomplete for selected continuing people.
- **Failure recovery and boundedness are incomplete.** Exhausted invalid output seals a source window without a user retry path. A new trigger arriving during an existing pass joins that promise without scheduling a follow-up window; sandbox idle/startup only resumes already-prepared operations, not unprocessed backlog. Event-count limits do not themselves budget long input text; the new hard input cap prevents exposure/spend but can fail a meaningful window rather than consolidate it usefully. Scheduler Room candidates remain unbounded and salience projection writes are not transactional/recovered with publication. Passing the narrow crash cases does not close these requirements.
- **Live product proof remains absent.** The supplied Electron script captures a registered handler and calls `trigger({}, input)` directly. That is a real Electron main-process/domain test, not renderer IPC transport, a mounted Conversation exchange, close/reopen, or maintenance UI verification. Neither prior harness checks the semantic correctness of generated output; they label PASS when rows exist. Current real-provider verification failed (below). Mounted automatic foreground/idle/reload/failure behavior must be verified as part of V08, not reclassified as V09 polish.
