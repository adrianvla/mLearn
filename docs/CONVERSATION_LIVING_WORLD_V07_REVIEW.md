# V07 adversarial review — 2026-09-15

## Verdict: V07 closed — corrected protocol is the first supported Living World format

The original W1–W5 protocol was **not atomic or crash-safe**. W1 published people, current membership and situation before the asserted logical commit. W2 was ordinary visible membership history, and all three Sea read APIs exposed W3 admissions without checking W4. `getWorldState` queues behind startup reconciliation, but `loadWorld`, journal IPC and main-side Sea consumers do not share that barrier. Recovery could fail, label the operation interrupted, and leave the published topology behind. A retry eventually succeeding did not establish isolation.

New operations have been corrected and crash-tested. **Release-history audit:** no released mLearn version contains any Living World persistence code — the feature is absent from every release tag through v2.9.11, and `src/electron/services/integration.ts` has never been committed. Per product decision, the corrected V07 hidden-preparation + atomic-publication protocol is therefore the **first supported Living World format**. No migration, rollback or compatibility machinery exists or is needed for intermediate development-era W1–W5 prefixes or pre-link adoption records: current code cannot produce them (every ledger write carries a `prepared` before-image at W1; every adopted participant carries the immutable `adoption` link, preserved across profile edits), and development-era worlds are discardable. Should such data nonetheless exist, it fails closed: a prepared-less pending record settles as interrupted and is never certified or silently rolled back, and journal rows claiming an integration provenance without the staged marker stay quarantined from every canonical Sea reader — including the recovery/dedup readers — so an operation ID reused from dev-era data cannot resurrect old rows.

## Corrections

- **One publication decision.** W1 now saves private prepared content in the ledger, leaving canonical participants/Rooms unchanged. W2 membership, W3 memory and the final journal marker carry `stagedIntegration`. Sea projection, subscription and query filter these rows until the ledger is committed. The sole logical commit is a final atomic `world.json` rename publishing entity changes and committed status together. The journal marker is preparation, **not** the logical commit.
- **Recovery independent of source lifetime.** The prepared operation contains the selected drafts and destination before/after state. Recovery verifies the destination and referenced identities, resumes matching journal rows, and publishes once. Transient I/O remains pending/retryable. A proven destination/journal conflict becomes interrupted with no canonical prepared effects. Prepared content is stripped from renderer snapshots and removed on successful commit.
- **Adoption identity survives development.** Adopted people carry an immutable source-Thread/baseline-hash link. The hash verifies the pinned sandbox record, not the person's current persona. Normal profile updates preserve the link; subsequent integrations never overwrite an adopted person's developed profile. A changed pinned source or an unrelated ID collision fails instead of binding silently.
- **Witnesses are not current members.** Memory witnesses/owners/relationship targets require canonical identities, but do not join a Room. Only selecting a situation adds its declared cast to that Room. Selected historical witnesses retain access despite later departure; current members acquire no retrospective witnesshood. The compiler and Memory Browser use this distinction.
- **Useful material without Room scaffolding.** SCOPE-06 and MODEL-02 do not require Room membership to adopt a person or personal memory. The world-continuity journal destination supports those operations without inserting a Room. Situation adoption still requires a real Room. Normal retrieval includes world continuity, and new sandbox baselines pin its journal head. Memory Browser exposes it and includes historical witnesses in the relevant perspective choices.
- **Consequence-level claims.** Distinct memory consequences derived from one underlying event remain independent. A different manual interpretation does not consume the source globally. Identical selected consequences are claimed per destination; operation identity/hash remains global. A separate deliberate destination is a distinct admission, not a retry. Pending reservations are reported as pending, not “already integrated.” Retracted source memories are excluded.
- **Recovery and selection UI.** Pending operations can be retried with their durable operation ID after reopening, including from Conversation when the source Thread is gone. Interrupted records expose current affected topology. Auto-selected dependencies drop when their source selection is removed. Successful recovery clears the old error and shows completion. Narrow layout no longer lets an admission badge squeeze the item text into one-word lines.
- **First supported format, fail closed.** Release history (no Living World code in any tag through v2.9.11; `integration.ts` untracked) established that intermediate V06/V07 formats never shipped. No migration machinery was built. Canonical Sea visibility requires a `stagedIntegration` row backed by a committed ledger record; the recovery/dedup readers require the marker too, so dev-era unstaged rows stay quarantined even when an operation ID is reused. Prepared-less pending records are refused (`[world] pending integration has no prepared before-image; review required`) and settled interrupted. The v1 `AgentConfig` KV migration (`legacyMigration.ts`) is unrelated shipped-data support and is retained.

No autonomous-life implementation, Dreamer expansion, initiative, or Scenario evolution was undertaken. Existing Dreamer code was exercised without modification. Scenario creation was touched only to pin the new world-continuity journal in sandbox baselines.
